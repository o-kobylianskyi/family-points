## Work package B0 — security / database integrity, mandatory before integration
1. Review read and write permissions for every target `WORKSPACE COVER/ICON`, `MEMBER AVATAR`, `MEMBER_GROUP ICON`, `WORK_NODE(GROUP) ICON`, `TASK ICON`. Enforce target-specific authorization in `effective`, `getBoundVariant`, `upload`, `bind`, `clear`: workspace membership is NOT sufficient to expose restricted target images. Validate `WORK_NODE` type and active/deleted entities; allow self-avatar only under explicit policy. Do not use `MANAGE_TASKS` as blanket permission for people groups; reconcile scoped delegation/group roles.
2. Enforce strict cross-workspace association/read isolation, including guessing asset UUID, variant URLs, reference binding, private catalog scope and switching from one family to another. Return safe 403/404 without asset metadata leakage.
3. Complete safe upload: size/pixel/decode limits and memory protection, MIME sniff/decode/re-encode, EXIF/GPS removal, no dangerous SVG/remote imports, valid JPEG/PNG/WebP policy, negative upload payload tests, limits on unbound orphan uploads, per-workspace size/asset quota. Backend and Release review initial 100 MiB/workspace planning cap.
4. Apply optimistic version checks to **assign AND clear**, handle simultaneous editors/concurrent reads, audit actor/workspace/ref changes without bytes and ensure rollback preserves bindings/ledger.
5. Keep media Flyway **V36** and calendar Flyway **V35** distinct. Integrate a candidate containing BOTH migrations and verify clean + upgrade Postgres history; never merge/deploy V36 first without validating V35 order. Do not retroactively rewrite a migration applied to a persistent database.
