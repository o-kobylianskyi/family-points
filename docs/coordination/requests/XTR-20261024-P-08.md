## Scope
1. Review all workspace-owned tables/FK deletions/retention and existing PostgreSQL backup/restore pipelines. Test reset solely on disposable/restored fixtures from synthetic two-family data — NEVER on live family, never by ad-hoc SQL.
2. Propose encrypted pre-reset export/snapshot, storage quota/retention and secure owner-only retrieval with cross-workspace privacy. Distinguish "data export" from actual selective restore; cannot advertise Undo until recovery flow is implemented/tested.
3. Exercise data integrity and transaction rollback under half-failed deletion/media cleanup, concurrency and interrupted execution, stale clients/offline replay, Android policy persistence and login recovery.
4. Coordinate schema migration numbering with open calendar/media PRs and starter templates. Verify old Web/Android version behavior to reset generation and new onboarding status, security access logs/rate-limits, no platform admin/child bypass.
5. Maintain explicit independent user authorization before BETA/PROD or any destructive actions, CI/sha pinned release, and tested emergency recovery. Publish accurate NO-GO/GO verification.

## Acceptance
- [ ] Disposable two-family reset test proves other family untouched; admin can log in
- [ ] Snapshot/export/backups and retention assessed and real restore tested or restoration explicitly unsupported
- [ ] Resource/PK/FK/media consistency, ledger normalization, queued offline operations and device policy warnings exercised
- [ ] Failure and retry scenarios documented with exact evidence, approved API consumers and release SHA
- [ ] No live database mutation, deploy or rollback performed without separate approval
