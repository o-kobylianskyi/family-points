# XTR-20261024-A-03 — P0 immutable account identity for Android offline isolation

- Origin: Android. Owner: Backend / Architecture. Status: OPEN; blocks completion of account-scoped offline queue migration.
- Existing Android `CurrentUserResponse` contains username, workspaceId and memberId but no immutable global account identifier. `OfflinePointsQueueStore` partitions only by workspaceId + viewerId (memberId); multiple global accounts may share or switch a workspace member.
- Checked Backend source `JwtService`: JWT subject is username, not immutable account ID. Renaming username would change this identifier. Android cannot safely infer account identity from username or member ID.
- Required: add a stable, opaque accountId to authenticated `/api/me` response (and documented scope/verification semantics) without exposing raw secrets; confirm behavior of account switching and Google/password dual identity. Publish tests showing global account A vs B sharing a workspace member.
- Migration safety: previously queued entries lack account owner. DO NOT assign them to whichever account logs in first; propose explicit ownership verification/one-time migration or quarantine + user-confirmed recovery, keeping data durable and never replaying ambiguous legacy entries.
- Android upon stable contract: migrate local SQLite queue to owner key, partition all pending/confirm/replay operations by (accountId, workspaceId, memberId), ensure replay JWT's verified session account matches owner, add migration, multitenant and cross-account regression tests.
- Until then: current Android offline queue must not be declared completely account-isolated; avoid guessing ownership and avoid silent deletion.
