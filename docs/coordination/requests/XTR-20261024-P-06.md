# XTR-20261024-P-06 — Web: family admin reset center with checkboxes and password gate

- **Status:** AFTER_INTERIM_BETA / ON HOLD — no destructive-reset implementation before interim BETA or explicit user reprioritization
- **Initiator:** P Architecture / Planning, 2026-10-24
- **Receiving owner:** W Web
- **Base:** `main` `b9ae8c1155ae5b56eabee052f8639a667787366d`; inspect current SettingsPage and user auth
- **Priority:** P1, security-sensitive
- **Depends:** ADR-FAMILY-RESET-001, IMP-0009, Backend XTR-20261024-P-05, template wizard XTR-20261024-P-02

## Scope
Create **Settings → Family administration → Reset/Restart family** (Danger Zone), visible only to authorized family owners/admins. Three modes Restart progress, Selectively clear, Start family setup again. Render server-supported groups with checkboxes and explicit "keep" versus "clear", all initially unchecked in custom mode; presets may select a reviewed safe set. Display impacted counts, reset history/balance distinction and dependency blockers from Backend preview. No client-side deletion decisions or hard-coded assumed cascading behavior.

Flow: select → validate through pure Backend preview → edit dependency warnings → confirm family name and independent irreversible acknowledgment → enter **current password** for fresh server-side reauth (or verified provider step / set local password flow) → one-time execute with idempotency → receipt/status → only after success navigate to existing first-family wizard. Disable duplicate submits; 401/403/409/429/stale-preview and failure/retry states. Display warnings for children, device policies, non-owner accounts, media backups and retention. Provide optional secure export route only if Backend/Release actually supports it.

Light/dark Soft Family, responsive desktop/mobile, accessible labels and clear destructive button, localized uk/de/en/ru. Existing global account password-change flow must not be mistaken for reset authorization. No real deletion tests on shared BETA/prod.

## Acceptance
- [ ] Unauthorized actor sees no destructive UI; backend also denies regardless of UI
- [ ] Each selectable group shows cleared/retained state and exact server counts/dependencies
- [ ] Bad password and stale preview cannot wipe; page preserves selection on safe errors, no duplicate requests
- [ ] Reset + open wizard + apply minimal starter pack against isolated test workspace works
- [ ] No UI promises "undo" without tested restore, and Web build, screenshots/i18n/a11y validated
- [ ] Contract ACK and evidence linked in Web journal and IMP-0009
