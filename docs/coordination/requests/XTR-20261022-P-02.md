## Delivery scope
1. Implement common workspace calendar UI with day/week/month/bounded range selection, member/type filters, clear visual distinction TASK vs REWARD_WINDOW and status badges. Same selected calendar event opens existing authorized task or reward detail; preserve current task workflows.
2. Render future virtual task occurrences + persisted instances from server endpoint. `scheduledTime` on existing task slots is a **due/deadline**, not an execution start. Show tasks on the correct date, preserve slotKey/occurrenceKey in deep-link actions, no fabricated record rows.
3. In reward creation/edit, add time availability configuration: ALWAYS; ONE_TIME date-time interval; RECURRING_WEEKLY weekday checkboxes, effective date range and multiple windows; time input in workspace zone; validate and display errors; preview next window. Keep task prerequisite editor, point types, reputation, approval, cooldown, quotas and duration unchanged.
4. Catalog reward cards and purchase/request UI show schedule availability and accurate next opening separately from unmet task/points/approval requirements. Disable unavailable action for UX; authoritative refusal handled after click, with localized error reasons. A pre-approved request may be temporarily outside purchase window without losing approval.
5. Reuse approved Soft Family light/dark styles; responsive desktop/tablet/phone; keyboard/screen reader labels and UA/DE/EN/RU translations. Do not replace existing styling work with a premature calendar branch.
6. Consume versioned server API; older deployment without endpoint must degrade safely (feature flag/error state) rather than blanking rewards/tasks.
