## Decision packet from Backend

1. **Owner model:** workspace-local `WorkspaceMember` avatars and family cover/avatar; separate optional account-global profile avatar only if authorization and visibility are explicitly specified. MemberGroup is for people; WorkNode(GROUP) is for task hierarchy. No implicit sharing of private images across workspaces.
2. **Image slots:** family COVER and ICON, member AVATAR, MemberGroup ICON, WorkNode(GROUP)/task-category ICON, TaskDefinition ICON override. For TaskDefinition: own selected/uploaded image → effective nearest task hierarchy/category icon → curated default. Removing override restores inheritance. TaskInstance should reference definition/effective image, never duplicate binary.
3. **Content model:** immutable random media ID and scoped ownership metadata; image binaries in durable object store/filesystem with transactional metadata and delayed garbage collection. Curated defaults with stable catalogue IDs/version; no editable paths/URL injection. Decide whether VPS durable volume or object storage and backup/rollback policy together with Release.
4. **Access design:** only authorized workspace member can view private media; upload/assign/delete requires object-specific edit rights; prevent guessing IDs, cross-family associations, public CDN leaks, signed-URL misuse and child-to-parent privilege escalation. Document child/avatar self-management separately.
5. **Processing:** allow JPEG/PNG/WebP only after server-side magic-byte/decode checks; max bytes/pixels/aspect, decode limits, re-encode, remove EXIF/GPS, safe thumbnails, safe Content-Type/nosniff. No executable SVG or untrusted remote fetch, zip or arbitrary local paths.
6. **API contracts (proposed, not final):** catalog listing; multipart upload with scoped media owner; authenticated media read/thumb; target-specific PUT/PATCH assignment/removal; additive `effectiveImage` metadata + `imageSource=OWN|INHERITED|DEFAULT`; legacy PUT clients must preserve images when field omitted. Decide version/ETag and caching.
7. **Lifecycle:** uploaded assets can be shared only within authorized workspace by explicit reference; garbage collect only unreferenced media after safe delay; preserve storage during DB restore; DEV/BETA/PROD separation; cost and quota limits.
