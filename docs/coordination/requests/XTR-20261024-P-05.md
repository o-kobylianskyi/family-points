## Scope
1. Inventory actual FK references and retention policies for family members/global account memberships, group/task hierarchy and histories, TaskInstance/Audit, reward purchases/requirements/obligations, member/group point transactions, reputation, balances, funding, invitations, uploaded media and managed devices. Produce **data category dependency DAG** and testable supported reset mask combinations, not naïve `DELETE FROM families` or universal cascade.
2. Preserve Workspace ID and original authenticated owner/active admin membership; never delete another workspace or shared global UserAccount. Verify admin authorization scoped to specific workspace and fresh password via server authentication. For Google-only, require equivalent explicitly verified reauth or secure password-setup first. Implement short TTL one-use challenge bound to preview/scope/actor/workspace generation, rate limit and audit.
3. APIs: capabilities, pure read-only exact-count preview with blockers and fingerprint, new-password/provider challenge, execute idempotently with explicit family name and selection, status. Prevent preview/execute time-of-check race and double-submit.
4. Implement safe transactional reset for validated category combinations. For balances-only with transaction history retained, use auditable **reset ledger adjustments**; for histories purged, reconcile FK/reward obligations and resulting balances. No automatic credits, purchases, fake TaskInstances or unlinked orphan rows.
5. Rotate `workspaceDataGeneration` epoch on destructive completion and reject pending offline queued mutations or stale client state, including members who remained logged in. Ensure device policies safe, no unexpected Android Device Owner policy removal. Revoke active invites/sessions as selected; targeted invalidation without logging other workspace users out.
6. If resetting for fresh onboarding, mark setup DRAFT / restart existing onboarding wizard and clear selected import provenance only where necessary; owner credentials/member remain valid. If only partial reset, do not trigger wizard unless explicitly requested. Integrate with template installation XTR-20261024-P-01 and preserve catalog as global read-only.
7. Add secure audit, metrics and backup/export/restore policy (review with Release). Only expose UI checkboxes supported by tested execution. No real database destruction during implementation without isolated disposable fixtures.
