## Verified Backend state (source)
- `GET /workspaces/{workspaceId}/setup` returns `SetupState(workspaceId,dataEpoch,revision,status,steps,completedAt)`.
- `PATCH /workspaces/{workspaceId}/setup/steps/{stepCode}` accepts `{status:"COMPLETE"|"SKIPPED",expectedRevision:number}`; checks request epoch, revision, manager permission.
- `POST /workspaces/{workspaceId}/setup/complete` accepts `{expectedRevision:number}`; checks persisted step statuses.
- `WorkspaceSetupService.STEPS`: MEMBERS, MEMBER_GROUPS, WORK_NODE_GROUPS, CATALOG_SELECTION, TASK_REVIEW, REWARD_REVIEW, FINAL_REVIEW.
- Setup is feature-gated via `familypoints.setup.enabled:false` and has **no import/activation side effects**.
- The current controller/service expose **no** `/setup/review`, `/setup/commit`, or immutable operation receipt endpoints. Do not call them from clients.
- A saved COMPLETE/SKIPPED step denotes **metadata**, not proof of an imported/activated item; never display successful creation based only on this status.
- Existing families without a state row must not be auto-enrolled/overwritten.
