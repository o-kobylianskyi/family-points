- **Goal:** every visual image slot offers a bundled curated default illustration/icon library AND optional privately uploaded user image. No empty/broken image when unset.

## Domain targets and effective image resolution
1. **Account/member avatar**: personal avatar for a member/profile (including child profiles). Confirm whether identity-wide global account image and workspace-local member avatar are distinct; prefer workspace-local override when applicable, without allowing a family to read other families' media. Default curated illustration or initials.
2. **MemberGroup avatar**: group image/default icon (people groups, nested groups).
3. **Task group/category icon**: separate from MemberGroup, belongs to task taxonomy / WorkNode(GROUP) or existing category grouping as appropriate. Architecture to confirm precise entity because people-group and task-group differ.
4. **TaskDefinition image**: optional own selection/upload; **default inherits effective task-group/category image** when no override, then falls back to a curated task icon. TaskInstance should resolve via definition without duplicating image binaries or modifying historical ledger/execution records.
5. **Workspace/family image**: dedicated cover/hero picture, editable by authorized family manager; consider a separate square family avatar/icon for lists and workspace switcher. These are separate visual slots from members' avatars.
6. Future reward icon may reuse the same media/asset primitive, but should not block this package.

**Fallback precedence:** explicit custom upload/selected default for entity → task category inherited icon (tasks only) → system-curated default → initials/generic icon. Clearing task override must restore inheritance. If category image changes, non-overridden task images should update; overridden tasks remain stable.

## Backend-owned implementation / contract proposal (not prescriptive until ADR)
- Introduce scoped media asset metadata (immutable media id, owner workspace where applicable, mime, dimensions, byte size, status, origin UPLOADED/CATALOG, checksum, created/updated timestamps); avoid storing base64 in normal task/member list DTOs.
- Curated catalog: stable IDs, categories e.g. family, adults, children, task types, member groups, rewards; backend can reference a versioned static/packaged catalog with localized UI labels; don't trust arbitrary user-supplied file paths.
- Upload: authenticated multipart with server-side authorization and strict type/content checks (JPEG/PNG/WebP); size/dimension limits; process/re-encode and strip EXIF (including location); thumbnail variants, constrained aspect ratio/cropping metadata, size-bound responses; prevent SVG/script execution and image bombs.
- Access: enforce workspace ownership on upload, assignment, reads, update/delete. Child uploads/visibility according to scoped permissions, not global family admin for unrelated workspaces; no publicly enumerable private family images. Provide cache controls / signed scoped URLs or authenticated media endpoint as appropriate; never expose other workspace media by guessing ID.
- Persistent storage: design choice (DB object vs filesystem/object store) and backup/restore/lifecycle, reference counting/shared asset handling, deletion without breaking inherited/default image; DEV/BETA/PROD separation. Coordinate with Release before persistent volume changes.
- DTOs should expose stable `imageRef` / effective image URL + source metadata (OWN/CATEGORY/DEFAULT), and keep existing old clients compatible; upload/select/remove endpoints separately with optimistic concurrency where relevant.
- Asset catalog and assignment work with Web and Android on the same REST contract. New functionality must be additive; update handlers must **not clear images when older clients omit the property**.

- [ ] Family/member/member-group/category/task can select a catalog option or own photo with correct permissions.
- [ ] Cross-family media URLs/IDs and assignment are rejected; switching workspace cannot leak cache or media.
- [ ] Reject hostile MIME spoof, overlarge dimensions/files, malicious payload, EXIF retention, path traversal and unauthorized delete.
- [ ] Public defaults cached efficiently, private media protected; existing clients and entities unaffected by missing new fields.
- [ ] DB migrations, backup strategy, upload/delete cleanup, rollback and two-workspace negative tests pass before Release handoff.
