## Calendar: requested Backend handoff
1. Publish finalized `CalendarEventResponse` DTO and complete, realistic JSON examples for TASK and REWARD_WINDOW, including stable virtual occurrence identity `definitionId:date:slotKey`, nullable task instance ID, task **deadline** vs reward **acquisition time window**, and event status fields.
2. Specify how every response provides or references the authoritative workspace IANA time zone. Android must convert ISO instants correctly across DST; it must not authorize reward purchase from local time or equate `scheduleOpenNow` with final eligibility.
3. Specify bounded range behavior (inclusive dates, 62-day/2,500-event cap), truncation/error semantics and permission-scoped member selection. Clarify whether filtering by MemberGroup is supported, or explicitly defer it with client-compatible fallback.
4. Preserve compatibility for existing reward PUTs; document 409 `REWARD_OUTSIDE_AVAILABILITY_WINDOW` and final purchase authorization; no invented offline writes.

## Media: requested Backend handoff
1. Provide final exact target type/slot literals for WORKSPACE COVER and ICON, WorkspaceMember AVATAR, MemberGroup ICON, WorkNode(GROUP) ICON and task own/inherited ICON; distinguish member avatar from global account identity.
2. Finalize effective image reference/DTO fields (including OWN/INHERITED/DEFAULT, version/ETag), bindings, optimistic `expectedVersion`, clear behavior, errors and tenant/target-level access. Document whether `effectiveImage` is embedded in family/member/group/task DTOs or requires another authenticated request.
3. Clarify supported upload MIME/size/dimensions and WebP policy, server-supported COVER/CARD/THUMB/ICON/AVATAR variants, catalog-key previews and stable SVG preview auth/cache contract. The 15 bundled SVG catalog images noted in draft are acknowledged; do not assume Android can render server SVG natively without a decoder strategy.
4. Specify cache invalidation/version rules and permission revocation behavior for native authenticated private-image reads. Android will isolate any offline cache by global account, workspace, authorization context and asset version, and purge on logout/workspace switch.
5. Complete all target-specific ACL, two-workspace negative checks, validated image sanitization, real curated asset availability, quota/orphan lifecycle and backward compatibility tests before declaring API ready.
